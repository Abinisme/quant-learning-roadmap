起源与哲学 基础

传奇实验 · 核心信念 · 四大支柱

一个改变交易史的打赌
1970s — Richard Dennis 从芝加哥期货交易所的跑单员起步，靠几百美元本金做到上亿美元身家，被誉为"交易厅王子"。
1983 年夏 — Dennis 与合伙人 William Eckhardt 发生激烈争论：成功的交易员是天生的还是可以培养的？Eckhardt 认为是天赋，Dennis 认为是纪律。
1983 年秋 — 两人决定用实验验证。他们在《华尔街日报》《巴伦周刊》《纽约时报》刊登广告招募学员，措辞是："交易员培训生，无需经验。"
1983 年末 — 从 1000+ 申请者中筛选出 23 人（有扑克牌手、会计师、退伍军人、甚至一个 19 岁的高中毕业生），进行两周封闭培训。
1984-1988 — Dennis 给每人 50万-200万美元真实资金。四年后，这群"海龟"累计盈利 超过 1 亿美元。
后续影响 — 海龟实验证明：交易成功 7 分纪律 + 2 分系统 + 1 分天赋。这张"可以培养"的结论，开启了全球量化交易培训的序幕。
核心信念
截断亏损，让利润奔跑。
Cut losses short. Let profits run.
  • 不要预测市场方向——跟随已经发生的趋势
  • 你不知道哪一笔交易会赚钱——但你知道长期概率对你有利
  • 亏损不是失败，是交易成本——就像餐厅的租金和水电费
  • 情绪是交易最大的敌人——规则是唯一的朋友

市场选择

流动性优先 · 海龟交易池 · 现代迁移

海龟选市场的三条铁律
  • 高流动性：日均成交额足够大，百万级资金进出不会显著冲击价格。Dennis 的标准——你的一笔交易应该像一颗石子投入大海，不起波澜。
  • 趋势性：历史上出现过清晰、持续的长期趋势。海龟是纯粹的趋势跟踪系统——在横盘震荡市中会持续小额亏损，必须靠趋势行情中的大盈利覆盖。
  • 多样性：多个不相关市场并行。外汇、利率、金属、能源、农产品——覆盖面越广，总有一个市场在走趋势。

如何评估一个新市场
1
流动性测试：日均成交额 > 你的最大单笔资金的 100 倍。如果你计划每笔投 10 万，标的日均成交需 > 1000 万。
2
趋势性测试：计算过去 5 年"连续上涨超过 30%"的次数。频次越高，海龟越有利可图。
3
相关性测试：与该市场你已有的品种的相关性 < 0.5。如果高度相关，不能算作"分散"。
4
成本测试：双边手续费+滑点 < ATR(20) 的 20%。如果交易成本太高，信号会被摩擦吞噬。

头寸规模——整座大厦的基石 核心

N 值 · ATR · 头寸单位 · 波动率标准化

为什么仓位管理比选股重要 100 倍

绝大多数交易者把 90% 的精力花在"该不该买"上，只花 10% 在"该买多少"上。 海龟反其道而行——入场信号极其简单（涨破 20 日高点就买），但仓位计算极其精密。 原因：你无法控制市场涨跌，但你可以精确控制每笔交易承担多少风险。

假设你有一个胜率 60%、盈亏比 1:1 的策略。如果每次满仓 all-in，连续 3 次亏损就爆仓了——策略再"好"也没有机会兑现。 但如果每次只冒 2% 的本金，连续亏损 20 次后还剩 67%。你活到了概率兑现的那一天。 "仓位管理 = 生存管理。"
N 值——海龟的度量衡

N = ATR(20)，即"这个品种平均每天波动多少钱"。

True Range = max(当日高-当日低, |当日高-昨收|, |当日低-昨收|)
N = ATR(20) = True Range 的 20 日指数移动平均

True Range 考虑了三件事：当日振幅、向上跳空、向下跳空。跳空非常重要——如果昨天收盘 100，今天开盘直接跌到 95（-5%），即使当日最高最低只差 1 元，TR 也是 5 元。

头寸单位（Unit）

1 个 Unit = 该头寸每天波动 ≈ 账户总资金的 1%

Unit Size = (账户资金 × 1%) / (N × 合约乘数)

合约乘数：期货每手对应多少单位标的。如沪深 300 股指期货乘数 = 300 元/点，原油期货乘数 = 1000 桶/手。 股票无乘数 → 直接用价格。

🐢 交互式 Unit 计算器

输入参数，实时计算你应该买多少。这是海龟系统中最常被调用的公式。

为什么 N 值仓位管理是革命性的
传统做法
  • 每个品种买同样金额（各 10 万）
  • 原油波动 3% 和国债波动 0.3% 被视为同等风险
  • 回撤集中在高波动品种上
  • 组合风险不可控
海龟做法
  • 每个 Unit 承担相同的账户风险
  • 高波动→少买，低波动→多买
  • 所有品种贡献的风险均等
  • 组合风险可控、可预测
一句话总结：N 值仓位管理让你在原油上亏的钱和在国债上亏的钱" 感觉一样"——因为它们对账户的冲击被精确地标准化了。

入市策略 核心

系统一 (20日) · 系统二 (55日) · 过滤规则 · 双系统并行

入市设计的哲学

海龟的入场信号极其简单——价格突破 N 日最高/最低价就入场。这不是偷懒，而是刻意为之。 复杂的入场条件 = 更多的参数 = 更严重的过拟合 = 更差的实盘表现。 海龟把智力投入在仓位管理和退出策略上，入场只是"扣动扳机"——简洁但不简陋。

系统一：20 日突破（短线）
做多：价格 > 过去 20 日的最高价 → 以突破价买入 1 个 Unit
做空：价格 < 过去 20 日的最低价 → 以突破价卖出 1 个 Unit
特性描述
信号频率每年约 3-6 次/品种
持仓周期数天到数周
胜率约 35-38%
过滤规则如果上一次 20 日突破交易是盈利的 → 忽略本次信号
系统二：55 日突破（长线）
做多：价格 > 过去 55 日的最高价 → 以突破价买入 1 个 Unit
做空：价格 < 过去 55 日的最低价 → 以突破价卖出 1 个 Unit
特性描述
信号频率每年约 1-3 次/品种
持仓周期数周到数月
胜率约 40-45%
过滤规则无——每次 55 日突破都必须执行
系统一的过滤规则——为什么？

系统一的过滤规则是整个海龟系统中最"反直觉"的设计。它背后的逻辑是：

1
如果上一次 20 日突破交易盈利了 → 说明当前趋势发展良好，价格已经离开突破点较远。此时如果再出现突破信号，大概率是"追高"，风险收益比不佳。
2
如果上一次 20 日突破交易亏损了 → 说明趋势可能刚启动就夭折了（假突破），或者是大的盘整区间被打破。此时再出现突破信号，可能是"真正的趋势的开始"。
3
关键：这个过滤只针对系统一。系统二（55 日突破）在所有情况下都必须执行——因为 55 日级别的突破太珍贵了，错过一次可能错过整个大趋势。

入市策略的常见疑问
问题答案
如果系统一和系统二同一天发信号？各买各的——它们是两套独立的系统，不会合并信号。
涨停买不到怎么办？海龟用"突破价"下单，不是"收盘价"。涨停板排队——大概率买不到，但规则如此。如果连续 3 天买不到，放弃本次信号。
跳空高开超过突破价？以开盘价买入（不是突破价）。海龟允许一个 Unit 的滑点容忍度。
同时做多和做空同一品种？可能！系统一做多+系统二做空同时持有——这被称为"价差效应"，实际上是一种自然对冲。

工程问题常见错误开源项目的解决方案
前瞻偏差 用当日最高价判断"是否突破20日高点"——但当日还没收盘，最高价还在变动。实盘中你这样判断，信号会不断闪烁。 backtrader 的 next() 方法只在 K 线闭合后调用一次，确保你看到的价格不会"回头修改"。freqtrade 更激进——内置 lookahead-analysis 命令自动扫描策略是否存在未来函数。
信号重复 同一根 K 线上触发多次买入（连续调用 buy()），导致实际仓位远超预期。 backtesting.py 提供 exclusive_orders=True 参数——每个方向（long/short）同一时间只能有一个活跃订单。新订单自动取消旧订单。这是生产系统的基本保障。
跳空处理 突破价格是 100 元，但第二天开盘直接跳空到 105 元——策略代码还是用 100 元模拟成交，回测严重失真。 backtrader 的经纪商模拟支持 slip_open 参数——当开盘价已超过突破价时，以开盘价成交而非突破价。配合 slip_fixed 滑点模型更真实。
指标计算时机 在 next() 中重复计算均线、最高价——性能极差且结果可能不一致。 backtrader 的 __init__ 中声明指标（框架自动缓存+更新），next() 中只读取。这个"声明-读取"分离是事件驱动回测引擎的经典设计模式。
实战启示：如果你用纯 Pandas 手写海龟策略，至少要做到两件事——① 用 shift(1) 确保入场信号基于"上一根已闭合 K 线"的数据；② 用一个 position 变量追踪持仓状态，防止同一信号重复下单。

止损策略 核心

2N 硬止损 · 移动止损 · 为什么止损比入场重要 10 倍

2N 硬止损——海龟最后的保险丝

每笔交易的最大亏损 = 入场价 ± 2×N。这是不可协商的规则——没有例外，没有"再等等看"。

做多：止损价 = 入场价 - 2×N
做空：止损价 = 入场价 + 2×N
例：入场 200 元，N=3.5 元，Unit=285 股
止损价 = 200 - 2×3.5 = 193 元
最大亏损 = (200-193) × 285 = 1,995 元 ≈ 账户 100 万的 0.2%

注意：单 Unit 最大亏损约 0.2% 账户。即使 4 个 Unit 全部触发止损（极端情况），总亏损也 < 1%。

移动止损——利润保护机制
  • 持有多头时，止损位随价格上涨而上移，但绝不下移
  • 盈利超过 2N 后，将止损移至盈亏平衡点——这笔交易不会再亏钱了
  • 海龟真正的退出信号是通道突破（见模块 6），但止损位确保了"如果退出信号迟迟不来，我不会亏太多"
  • 移动止损 = 让利润自己保护自己。一旦有了安全垫，就永远不让盈利变亏损
不止损的数学后果
连续亏损次数概率（趋势策略）有 2% 止损后剩余无止损后剩余
3 次~25%94.1%取决于亏损程度
7 次~5%86.8%大概率爆仓
12 次~1%78.5%100% 爆仓
17 次~0.1%（海龟历史记录）70.9%—

Dennis 培训时反复强调的一句话："每笔交易的止损不是建议，是命令。违反一次，你就被开除。" 23 个海龟中，最成功的几个正是在连续止损 10+ 次后仍然严格执行系统的人。

止损的心理学——比数学更难的部分
你的大脑在亏损时会自动产生以下想法，每一个都是错的：
① "已经跌了这么多了，该反弹了，现在止损不是卖在最低点吗？"
② "这次不一样——基本面没变化，只是市场恐慌。"
③ "再等等，收盘前如果还不涨我就止损。"（收盘前已经多亏了 2%）

海龟的答案：止损不由你的大脑决定——由代码决定。 没有商量的余地。没有"这次不一样"。止损触发 = 立即执行。

退出策略与金字塔加仓

系统一 10 日退出 · 系统二 20 日退出 · 0.5N 加仓逻辑

退出 ≠ 止损

止损是被动防御（亏损触发），退出是主动收网（趋势反转触发）。 一笔交易有 3 种结束方式：被止损（亏损）、触发退出（可能盈利也可能亏）、到期平仓。

做多退出做空退出
系统一价格 < 过去 10 日最低价价格 > 过去 10 日最高价
系统二价格 < 过去 20 日最低价价格 > 过去 20 日最高价

退出参数恰好是入场参数的一半：系统一 20 日入场→10 日退出，系统二 55 日入场→20 日退出。 这个设计确保了"入场快、退出更快"——宁可提前下车，不要坐过山车。

金字塔加仓——让利润滚雪球

趋势确认后持续加仓，而非一次性满仓。这是海龟把"让利润奔跑"从口号变成数学公式的关键机制。

加仓规则
入场后，价格每朝有利方向移动 0.5N，加仓 1 个 Unit。
单一品种最多持有 4 个 Unit。
每次加仓后，所有仓位止损统一更新为最新入场价的 2N 止损。

例：入场 200 (N=3.5) → 涨到 201.75 加第2U → 涨到 203.50 加第3U → 涨到 205.25 加第4U。 此时平均成本 202.625，如果价格回撤到退出位，利润已经锁定了相当一部分。

提取自 jesse (7.9k★)、nautilus_trader (23k★)、quantstats (7.2k★) 和 pyfolio-reloaded (591★)——展示现代框架如何将海龟的原始退出/加仓规则升级为工程级实现。

工程维度海龟原版开源项目的生产级实现
止盈-止损联动 分别独立：止损=2N，退出=通道突破 nautilus_trader 支持 OCO（One-Cancels-Other）订单——止盈和止损挂在一起，其中一个成交则另一个自动取消。这是海龟"止损和退出各管各"思想的现代化：同一笔持仓上同时挂止盈+止损，互斥执行。
部分平仓 全仓进出——买就全买，卖就全卖 jesse 内置 partial fills——允许分批次退出。盈利超过一定阈值后先平一半仓位锁定利润，留一半博取更大趋势。这比海龟的"全仓退出"更灵活、收益更平滑。
退出质量验证 看最终盈亏 quantstats 的 profit_factor（总盈利/总亏损）和 recovery_factor（累计收益/最大回撤）专用于评估退出策略的质量——退出太早=盈利因子低，退出太晚=恢复因子低。pyfolio-reloaded 的 tear sheet 将"进场段收益"和"出场段收益"分开分析，一眼看出退出是加分项还是减分项。
冰山订单 市价单全量成交 nautilus_trader 提供 iceberg（冰山）订单——只显示订单的一部分，防止大单对市场造成冲击。对于需要平掉大仓位（4 Unit）的加仓策略，冰山订单能大幅降低因平仓造成的滑点损失——这在海龟时代是无法实现的。
核心启示：海龟退出规则的核心思想是"让趋势自己告诉我该走了"，而非预测顶部。现代框架继承这一思想，但加入了三个关键改进——① 订单联动（OCO 止盈+止损互斥）；② 部分执行（partial fills 分批退出）；③ 冲击控制（iceberg 隐藏真实仓位）。这些改进让退出不再是一个"全有或全无"的二元决策。

从这次实战中学到的五件事
1
前期回撤是正常的——第 3 天浮亏 $4,500（约 1% 账户）但止损未触发。如果不坚持，后面 $30,100 的利润就没了。
2
加仓放大了利润——如果只持有最初的 3 手（1 Unit），最终盈利只有约 $7,500。加仓到 12 手把利润放大了 4 倍。
3
退出时果断离场——不贪"再涨回 $87"。退出信号 = 离场，没有讨价还价的余地。
4
止损从未触发——这笔交易从始至终没碰到止损线。好的交易中，止损只是保险，不是主角。
5
一次交易不代表什么——$30,100 的盈利需要覆盖未来可能出现的 5-8 次连续小额亏损。海龟赚的是概率的钱，不是每笔都赚。

# 核心计算
N = ATR(high, low, close, 20)
unit = int(account * 0.01 / (N * multiplier))

# 系统一：20日突破 + 过滤
if close > highest(high, 20):
    if last_s1_result == "LOSS":
        buy(unit); last_s1_result = None

# 系统二：55日突破 · 不过滤
if close > highest(high, 55):
    buy(unit)

# 止损 · 不可协商
if position > 0 and close < entry - 2*N:
    sell_all()

# 加仓 · 每 0.5N 加一次
if close - last_add_price > 0.5*N and units < 4:
    buy(unit)

# 退出 · 系统一
if close < lowest(low, 10):
    sell_all()
